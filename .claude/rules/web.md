# Web (apps/web)

- Routes are files under `src/routes` (TanStack Router, file-based). `routeTree.gen.ts` is generated and committed. Route files export only `Route`; screens live in `src/screens/`. `_app.tsx` is the signed-in layout; `sign-in.tsx` is the only public route.
- Put anything shareable in the URL (which room, which filter, which vendor's panel is open: `/vendors?vendor=<id>`, OD-112; which estimate is being edited: `/jobs/<id>?estimate=<id>`, OD-119).
- Server state via TanStack Query through `@trpc/tanstack-react-query` (`useTRPC()` → `useQuery(trpc.x.y.queryOptions())`). One Supabase client (`src/lib/supabase.ts`, PKCE); the tRPC link attaches the access token. Zustand only for UI state that must outlive a route. No Redux, no context-as-store.
- Saves refresh through the shared lists in `lib/refresh.ts` (`useRefreshJobs`, `useRefreshPhases`, `useRefreshMoney`, `useRefreshShopping`), never a hand-picked set of `invalidateQueries`. Detail pages start all their queries from the route's `loader` (`lib/prefetch.ts`, not awaited, so the page isn't held back). Everything refetches only when who's signed in changes, not on the hourly token refresh (OD-115, Q136–Q137).
- Pictures in lists and tiles use `thumbUrl ?? url`: a 640px JPEG made in the browser at upload (`lib/thumbnail.ts`); the viewer and a room's cover band use the original. Admins make thumbnails for older pictures in Manage. Signed picture links are kept across refetches while under 45 minutes old (`lib/stable-links.ts`), so pictures don't download again (OD-115).
- Forms: react-hook-form + the shared Zod schema via `zodResolver` — the same schema the API validates with.
- Derived values (areas, totals, progress) come from the API, not computed in React.
- Tailwind v4 utilities in JSX. Extract a component when the same cluster appears three times. No CSS modules or styled-components.
- Phone and laptop are equal: every screen works at 375px wide and on a laptop. Touch targets at least 44px; nothing depends on a mouse.
- Vendors has no tab in the laptop top bar; it's reached from Jobs, so Jobs is marked current on /vendors (OD-112, Q126).
- The laptop top bar starts at 768px (`md:`); below that, the phone's bottom bar and Menu panel. Anything that sits above the bottom bar (toasts, the batch bar) switches at `md:` too (OD-111, Q125).
- Every page names the browser tab, most specific first ("Kitchen, Rooms, Reparo"): `PageHeader` does it from its title (`tabTitle` for a page inside a section), other pages render `PageTitle`. After moving to another page, focus goes to its `h1`. Unknown addresses show `NotHere` (in the shell) or `NotHerePage` (outside it); a page that breaks shows `PageError` (OD-111, Q123–Q124).
- Accessibility: semantic elements, a label on every input, keyboard-reachable actions, visible focus. Colour never carries meaning alone.
- Tests: Vitest, next to the code, for logic-bearing modules.

## Design system: Plaster and tape

Decisions and reasons: Linear → *Design system* doc. Values: `src/index.css` (the only place colours, type sizes and radii are defined — never hard-code a hex, px font size or one-off radius in JSX). Visual reference: the canvas linked from that doc, section D.

**Tokens (Tailwind classes).** Use the semantic names, not raw palette colours (`bg-neutral-*`, `text-gray-*` etc. are out).
- Surfaces: `bg-background` (page), `bg-card` (panels, fields), `bg-inset` (recessed areas, picture placeholders), `bg-band` (heading strips inside a panel, like Shopping's rooms; OD-99), `bg-bar` (top/bottom bars).
- Text: `text-foreground`; `text-muted-foreground` for secondary text. Nothing lighter for readable text.
- Lines: `border-border` for dividers and panel edges; `border-input` for anything you interact with (fields, outline buttons, selects) — it's the 3:1 one.
- Actions: `bg-primary`/`text-primary-foreground` is the dark main button; `destructive` is brick red, for delete-type actions, negative money and errors (OD-84). `status-done` green is for Completed and for Saved, nothing else.
- Status: `status-idle`, `status-progress`, `status-done` (+ `-tint` backgrounds); awaiting review is `bg-tape text-tape-ink`.
- shadcn's `accent` is a **hover background**, never the tape yellow.

**Tape yellow (`tape`) is reserved** for: what needs someone (awaiting review, the attention count), the tape-measure strip, and the current-page marker in navigation. Always a fill behind `text-tape-ink`, never text or an icon on a light background. Don't use it for buttons, links or decoration.

**Settled chips.** Paid in full, Chosen and Purchased use a neutral chip (`bg-inset`, check icon), not the Completed green. Idle chips (Unstarted, Cancelled, Unpaid, To buy, Declined) carry a faint ring of their text colour, because their tint equals the row hover colour (OD-114, Q130, Q150).

**Colour and money.** Money is in the normal text colour, with `tabular-nums`. Red (`text-destructive`) only when money goes negative or over budget. No green for "good" money; the Saved green is about the save, not the amount.

**Type.** Archivo (self-hosted). `h1`–`h3` get the narrow heading width from the base styles — use real heading elements rather than styling a `div`. Sizes: `text-4xl` 44, `text-3xl` 32, `text-2xl` 24, `text-xl` 20, `text-lg` 18 (a row's name, such as a shopping line or vendor; OD-114, Q135), `text-base` 16 (body), `text-sm` 14 (smallest). Nothing below 14px. Sentence case; no all-caps labels.

**Shape and depth.** `rounded-lg` (6px) on controls and chips, `rounded-xl` (10px) on panels. Separate sections with tone and a thin border, not a shadow on every card. Shadows only on things that float (menus, dialogs, the phone bottom bar).

**The tape motif** is the one bold element: money and progress bars drawn as tape measure (ticks along the top, dark fill for committed/done, yellow for what's left), drafting dimension lines for room sizes (a room's size is a small floor plan, `FloorPlan`: the room drawn to its proportions with length along the top, width down the side, area inside and the ceiling beside it, below on a phone; OD-128, Q180), the plan grid (`grid` token) only in empty states and picture placeholders. The budget tape splits its fill into spent (solid `tape-fill`) and committed (striped, `COMMITTED_STRIPES`); over budget the scale runs to the total, the budget's end is marked and labelled, and the overrun is red (`destructive`), with a matching legend swatch. In dark mode `tape-fill` is a lighter grey, 3:1 against the page and the yellow, so a full tape doesn't look empty (OD-109). Don't add other decorative flourishes, and no monospace "technical" labels.

**Components.** shadcn/ui on Base UI, Nova style, in `src/components/ui/`; `cn` from `@/lib/utils`. Add a component when an issue needs it — the CLI (`pnpm exec shadcn add <name>`) or, if it can't reach the registry, by hand from shadcn's source with the source commit noted in the file. Then adapt it to these rules before use: Nova's defaults are compact (32px controls, 14px text, faint outline borders, a 50% focus ring), which break the 44px, 16px, 3:1 and focus rules here. Use `<Button>` for every button (`variant`: default, outline, ghost, destructive, link); `buttonVariants()` to style a link as a button. The one smaller button: actions in a shopping row on a laptop look 36px tall with 14px text and a 16px icon, so the price outweighs them, with an invisible margin keeping the tap area 44px; phones keep full size (OD-82, Q54).

**Icons.** Lucide (`lucide-react`), outline, one stroke weight, always next to a text label. No icon-only buttons; no emoji as icons. On action buttons, only six get an icon (Workflow polish, Q8; OD-82, Q42; OD-99): Plus on "Add …", Check on "Mark as purchased", Pencil on Edit, PanelRightOpen on "Details" (opens a side panel), ListFilter on "Filter" (OD-99), and a check on "Saved". Those use `absoluteStrokeWidth` so the stroke matches the label's weight. A few controls also carry an icon by convention (OD-114, Q134): X on Close, Upload on the upload box, Phone and Mail on call and email links, and the picture viewer's Previous/Next arrows. Every other button stays text-only, Sign out and Manage lists included. A text link that opens a new tab ends with a small ExternalLink icon (Q43). The Appearance switch is the one control drawn with icons alone (Monitor, Sun, Moon on a sliding knob): the choice's name is written beside it and every position has a screen-reader name (OD-83).

**Light and dark** are chosen under Appearance in the account menu: Device (the default, follows `prefers-color-scheme`), Light or Dark, remembered in that browser only (OD-83). The choice is set as `data-theme` on `<html>` by a script in `index.html` before the app loads, so nothing flashes; `src/lib/theme.ts` keeps it in step afterwards. Dark tokens live under `:root[data-theme='dark']`, and Tailwind's `dark:` variant follows `data-theme`. Every new colour gets a light and a dark value in `index.css`, each contrast-checked on its own (text ≥ 4.5:1, control edges and focus ≥ 3:1). Check new UI in both modes. `.ink` puts a small surface in the other theme (dark in light mode, light in dark mode); it's for things that float over the page and must stand out: the batch bar, every Undo or other message (its action is the solid button), and an active filter chip. Inside it, use the normal tokens; they flip with it (OD-126, Q173–Q176).

**Motion** only answers something the person did (a status changing, a section opening, a save confirming, a row leaving a list). No page-load or scroll-driven animation. Reduced motion is respected globally in `index.css`: it keeps opacity fades of 150ms or less and drops movement, scale and blur (Workflow polish, Q6). Transitions name their properties (no `transition-all`). Button press is the 1px downward shift, not a scale. Tapes slide (300ms) when their number changes while you're on the page, including from zero: their fill parts are always drawn, even empty. A tape that first appears already filled doesn't move. The logo's stitch on Completed stays the one celebration (OD-131, Q188, Q190).

**Saving.** One-value edits on something that already exists save when you leave the field, with no Save button: a picture's caption, a progress photo's date and job, a room's notes and size, a job room's spec and notes, a phase's status, any status dropdown (Workflow polish, Q2). Side panels for things that exist (a shopping line, room, vendor, phase or job) are edited in place with no Save button (OD-82, OD-89); a job's room is added when ticked and taking rooms off asks first, because it removes their status and spec. In the shopping line's panel every field saves when you leave it and every dropdown when you pick, money included; a money change says what changed and offers Undo for 10 seconds (OD-82, Q37–Q53). Its purchase status is a three-way switch (To buy, Purchased, Returned) that saves on pick with Undo; Purchased takes the price as paid and Returned takes what was paid as what came back, both then editable (OD-85). Adding something, marking as purchased from a shopping row (it asks what was paid), other money (job costs, payments, estimates, the budget, which open in the side panel too, OD-90) keep a labelled button. Every save shows its state on the field's label line, right-aligned: Saving… in grey, Saved with a check in green, or Couldn't save with an alert in red, announced to screen readers; why it failed and Try again show under the field (OD-84, Q62–Q64). A control with no visible label (the panel's name heading, a status dropdown in a list row) shows its state beside it (Q66). Every error in the app, a save or a mistake to fix, is red text with an alert icon (`FormError`; Q65); an error shows under the row or control that failed, and only that row locks while it saves. A section that can't load uses `LoadError`: "Couldn't load the rooms.", why in household words (`loadProblem`, never the raw message), and Try again, which refetches only that section's queries. Every section shows loading, a load error and empty as three different states; never "No … yet" while it's still loading (`FileSection` takes the query as `source` for this; OD-110). The last save wins; there is no edit-conflict check (Q4).

**Batch editing.** Shopping has Select: a checkbox per row and Select all per room, then a bar pinned to the bottom with the count (and how many are hidden by search or filters) and the actions. Each batch saves in one transaction (`updateMany`, `removeMany`) and offers Undo for 10 seconds that puts every line back; Remove asks first (OD-101). While selecting, picked rows are tinted (`bg-accent`, edge to edge), a click anywhere on a row ticks it, the rows' own buttons step aside, the bar says "N items, $X selected" with actions named as verbs ("Move to room…", "Set category…", "Set job…"), and Escape leaves Select mode (OD-104). Removing one line from its panel matches: a red Remove, "Yes, remove / Keep", and Undo (`ConfirmRemove strong`, OD-103). `ConfirmRemove` is the app's only confirm step: asking focuses Yes, Keep returns focus to the button that asked. Rooms, jobs, archiving a vendor and budget entries use the red `strong` version, with Undo for 10 seconds wherever the API can restore the item (rooms, jobs, vendors, shopping lines). A room with lines or jobs on it can't be removed: the confirm says what's attached and how to move it, with an OK instead of Yes (OD-113).

**Shopping list.** A tape-measure strip under the opening sentence shows bought (dark) against left to buy (yellow), following the filters and search (OD-107). Rooms fold one at a time (Fold / Unfold on the strip) or all together (Fold all / Unfold all); they start open and the choice isn't kept (OD-105). Purchased and Returned fold the same way, with Fold / Unfold, and start folded (OD-108). On a laptop, a row with no picture in a list that has pictures shows a plain `bg-inset` tile, so the column never looks like a gap (OD-108). A to-buy line with no price says "No price yet" in grey (OD-106). A filter in use is a small `.ink` chip (32px look, 14px text, 44px tap area) with an X; renaming a store everywhere is a text link at the end of the Store hint, naming the store (OD-126, Q173–Q174).

**Jobs.** The chosen estimate's quote line says "From the {vendor} estimate"; its Edit opens the estimate and it has no Remove. Choosing an estimate and marking one declined offer Undo for 10 seconds; adding every room to a job asks first with the count. On a phone, Price, Paid and Still to pay are label-and-amount rows (OD-119). Under a job's title a summary strip gives its status, Still to pay with its paid-of-price tape, and the vendor with Call and Email; "How it's going" and its rooms are one panel, and the progress tape shows only once something is done; a job with no rooms has no such panel, and its status is picked in the summary strip (OD-129, Q181). An empty section on the job page (Estimates, Drawings, Paperwork, Progress photos, Spec) is one line: heading, "Not added yet" and its Add buttons (`FileSection` `emptyLine`). The Jobs list says "paid" only above $0.00 (OD-120, Q148–Q149); "See all vendors" is an outline button beside "Add a job" (OD-129, Q184). Sections inside a panel are separated by a rule with more space above (mt-8, pt-6) than between a heading and its content.

**Rooms.** Under a room's heading, `BoughtTape` shows what's bought for it against what's left to buy, with both amounts, from `rooms.get` (`shopping`; OD-118). The room page runs heading, Jobs, What we're buying, Pictures, then Size and notes; without a cover the page starts with its heading (no band; OD-129, Q182), and a room with no pictures has one "Add pictures" row with a kind to pick. On a phone the Rooms list drops the empty thumbnail and puts the progress words on their own line (OD-117, Q139–Q140).

**Home.** The phase panel's heading comes from its jobs ("Phase 1 is on; nothing has started yet", "Phase 1 is underway"; one spelling, underway), with the Phases list's "done" tape and its "See all" links together at the top. Rooms run needing someone, then in progress, then the rest; a room without a cover gets a compact tile, never an empty placeholder; names are headings. With nothing waiting, Needs you is one line under the greeting (OD-116).

**Money.** Money in or out is a two-way switch (Money in, Money out) with an amount that has no sign (`adjustmentFormSchema` gives it one); the button names the result ("Take $5,000.00 out") and saving shows a message with Undo for 10 seconds, as does editing one. The breakdowns run biggest first (`bySize`), end with a Total row, and each name links: a category or room to Shopping filtered to it, Jobs and Shopping to their pages, a phase to it on the Phases page (`#phase-{id}`); phases stay in their own order; By phase's two tables share column widths so the amounts line up (OD-129, Q183). The budget's notes show under the starting balance, and its panel and button both say "starting balance" (OD-121, Q151–Q153).

**Phases.** A phase's `active` status reads "Underway" everywhere (`PHASE_STATUS_LABEL`; the stored value is unchanged). Beside each status is what it does to the money (`phaseMoneyEffect`: "Counts toward Committed" or "Not counted until it starts"). Changing it shows a message with Undo for 10 seconds; marking a phase complete with jobs still open says so in that message and under the phase until they're done. A phase's job count links to `/jobs?phase={id}` (the Jobs list for that phase, with "Show every phase"), and its panel lists its jobs with their status (OD-122, Q154, Q156–Q157). Each phase shows Spent and Still to come, and a phase that isn't counted yet what it would leave (red when short), from `phases.list` (`money`), the same figures as Money's By phase (OD-123, Q155).

**Vendors.** A vendor's row shows their phone as a tap-to-call link. Their panel puts contact first (Call and Email, then Phone and Email fields as `tel` and `email` inputs), then their jobs from `vendors.work`: each with its status, the chosen quote and what's been paid, then their open estimates (requested or received), each linking to the estimate. In the vendor picker, "Clear vendor" offers Undo for 10 seconds (OD-124, Q158–Q161).

**Manage.** Merging a category starts on an empty "Pick a category" and asks first, naming the whole consequence ("Merge Rugs into Furniture: moves 7 lines, removes Rugs."), then says it's done; there's no Undo because there's no un-merge. Opening Rename or Merge focuses its field, Escape cancels, and closing hands focus back to the button; Save is off while the name is blank. On a phone the field takes its own line. The API words a schema failure as the schema's messages (`errorFormatter` in `trpc.ts`), never raw JSON. The Appearance switch's knob is the text colour with the picked icon in the page colour, so the choice reads in light and dark (OD-125, Q162–Q165).

**Editing.** Multi-field edits and adding things open in the side panel (`Sheet`): from the bottom and nearly full height on a phone, from the right at about a third of the width on a laptop, with the page visible behind (Q16). Nothing swaps out a whole page to edit. Opening a panel or editor focuses its first field, except a panel that opens for reading, like a shopping line's, which focuses the panel so a phone doesn't raise its keyboard (OD-82); closing it returns focus to the control that opened it; leaving with unsaved changes asks "Discard your changes?" in the panel or form (`DiscardQuestion`), never the browser's dialog, except when closing the tab (OD-114, Q138). Status dropdowns stay usable while they save; the last pick wins (Q131). A side panel's name field shows a faint underline at rest (Q132).

**Forms.** One field per line, in every form and panel (OD-82, Q46). Short values keep a short field, about 12rem (`max-w-48`): money, how many, dates, and length, width and height (Q52). Nothing asks for an order number: lists are put in order with Change order, then Move up / Move down on each row (`MoveButtons`), and new rooms and phases go last (OD-117, Q141). An inline editor (a job room's spec) closes with Escape as well as Done, and focus goes back to its button (Q144). Every money field shows a drawn $ (`MoneyInput`, or `DollarBox` around an `AutoSaveField`; OD-106, OD-114). The exceptions are the Shopping filter bar and the status dropdowns inside list rows, which aren't forms. Dropdowns use `Select` (or `SelectChevron` on a styled one): the browser's arrow is hidden and ours sits 12px in, with 40px kept clear (Q45).

**Words on screen.** Household words, not database terms. Labels say what happens ("Mark as checked", "Record payment", not "Submit"). Avoid template habits: no "A · B" middle-dot strings, no "Word — fragment" labels, no "→" on buttons.

## Identity

Reparo is a tool for one house, not a generic project manager. Clear enough for someone non-technical: every action is a visible, labelled control (nothing hover-only or shortcut-only). Borrow Linear's feel (speed, calm, list → detail, instant feedback), not its look or power-user patterns. Use household words in the UI, not database terms. Design each screen for what it is: a room, a job, a phase, the money. The name is the mending charm; nod to it lightly. Chris reviews UI in the browser before it's committed.
